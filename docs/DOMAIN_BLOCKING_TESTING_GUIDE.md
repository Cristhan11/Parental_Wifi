## Quick Start

This guide provides step-by-step instructions to manually test domain blocking functionality on your Raspberry Pi.

### Prerequisites Verified ✅

- ✅ dnsmasq is installed and running
- ✅ dnsmasq config directory exists: `/etc/dnsmasq.d/`
- ✅ dnsmasq is configured to read from `/etc/dnsmasq.d/`
- ✅ Blocking scripts exist and are executable
- ✅ Devices registered in database:
  - CHILD Device: `e6:6a:8f:19:be:b1` (CP_ChildDev01) - Active
  - PARENT Device: `30:03:C8:0A:45:AF` (Laptop_Parentl) - Whitelisted

## Test 1: Basic Domain Blocking (Single Domain)

**Objective:** Verify that blocking a single domain prevents access to that domain.

### Step 1: Create Blocked Website via Web Interface

1. Open your web browser and navigate to: `http://[PI_IP]/blocked-websites/create`
   - Replace `[PI_IP]` with your Pi's IP address

2. Fill in the form:
   - **Device:** Select `CP_ChildDev01` (e6:6a:8f:19:be:b1)
   - **URL/Domain:** Enter `example.com`
   - **Block Type:** Select `Domain`
   - **Block Subdomains:** Leave unchecked (we'll test this in Test 2)
   - **Reason (optional):** Enter "Test blocking"

3. Click **"Block Website"** button

4. You should see a success message: "Website blocked successfully."

### Step 2: Verify Database Record

On your Pi terminal, run:

```bash
cd /var/www/parental_wifi
php artisan tinker
```

Then in tinker, run:

```php
$blocked = App\Models\BlockedWebsite::latest()->first();
echo "Domain: " . $blocked->domain . "\n";
echo "Block Type: " . $blocked->block_type . "\n";
echo "Device: " . $blocked->device->name . "\n";
echo "MAC: " . $blocked->device->mac_address . "\n";
```

**Expected Output:**
```
Domain: example.com
Block Type: domain
Device: CP_ChildDev01
MAC: e6:6a:8f:19:be:b1
```

Type `exit` to leave tinker.

### Step 3: Verify dnsmasq Configuration

On your Pi terminal, run:

```bash
# Check if config file was created
ls -la /etc/dnsmasq.d/blocked-domains-e6:6a:8f:19:be:b1.conf

# View the config file content
sudo cat /etc/dnsmasq.d/blocked-domains-e6:6a:8f:19:be:b1.conf
```

**Expected Output:**
```
# Blocked domains for device E6:6A:8F:19:BE:B1
# Generated by block_domain.sh

address=/example.com/127.0.0.1
```

### Step 4: Verify dnsmasq Service

On your Pi terminal, run:

```bash
# Check dnsmasq is running
sudo systemctl status dnsmasq

# Check recent logs for errors
sudo journalctl -u dnsmasq -n 50
```

**Expected:** dnsmasq should be "active (running)" with no errors.

### Step 5: Test DNS Resolution on Pi

On your Pi terminal, run:

```bash
# Test DNS resolution
dig @127.0.0.1 example.com +short
```

**Expected Output:** `127.0.0.1` (if blocked) or real IP addresses (if not blocked yet)

### Step 6: Test from Device

**Important:** Your test device (phone/laptop) must be:
- Connected to the Pi's Wi-Fi network
- Using the Pi as its DNS server (check network settings)

On your test device:

1. **Test DNS Resolution:**
   - Open terminal/command prompt
   - Run: `nslookup example.com`
   - **Expected:** Should return `127.0.0.1` (if blocked)

2. **Test Web Access:**
   - Open web browser
   - Navigate to: `http://example.com`
   - **Expected:** Should fail to load (connection refused or timeout)

3. **Verify Other Domains Work:**
   - Navigate to: `http://google.com`
   - **Expected:** Should load normally (not blocked)

### Step 7: Run Verification Script

On your Pi terminal, run:

```bash
cd /var/www/parental_wifi
chmod +x scripts/test_domain_blocking.sh
./scripts/test_domain_blocking.sh e6:6a:8f:19:be:b1 example.com
```

**Expected Output:**
- ✅ dnsmasq is running
- ✅ Config file exists
- ✅ Domain is in blocklist
- ✅ DNS resolves to 127.0.0.1 (BLOCKED)

### Test 1 Results

Document your results in `docs/DOMAIN_BLOCKING_TEST_RESULTS.md`:
- [ ] Blocked domain returns 127.0.0.1
- [ ] Other domains work normally
- [ ] dnsmasq config file created correctly
- [ ] dnsmasq service running without errors

## Test 2: Subdomain Blocking

**Objective:** Verify that blocking with subdomains enabled blocks all subdomains.

### Step 1: Create Blocked Website with Subdomains

1. Navigate to: `http://[PI_IP]/blocked-websites/create`

2. Fill in the form:
   - **Device:** Select `CP_ChildDev01`
   - **URL/Domain:** Enter `test.com`
   - **Block Type:** Select `Domain`
   - **Block Subdomains:** ✅ **CHECK THIS BOX**
   - **Reason:** Enter "Test subdomain blocking"

3. Click **"Block Website"**

### Step 2: Verify dnsmasq Config

On your Pi terminal:

```bash
# Check config file (should have leading dot for wildcard)
sudo cat /etc/dnsmasq.d/blocked-domains-e6:6a:8f:19:be:b1.conf | grep test.com
```

**Expected Output:**
```
address=/.test.com/127.0.0.1
```

**Note:** The leading dot (`.test.com`) means it blocks all subdomains.

### Step 3: Test from Device

On your test device, try accessing:
- `http://test.com` → Should be blocked
- `http://www.test.com` → Should be blocked
- `http://api.test.com` → Should be blocked
- `http://subdomain.test.com` → Should be blocked

### Test 2 Results

- [ ] All subdomains of test.com are blocked
- [ ] dnsmasq config uses wildcard pattern (leading dot)

## Troubleshooting

### Issue: Domain Not Blocked

**Symptoms:** Domain still resolves to real IP, not 127.0.0.1

**Possible Causes:**
1. Device not using Pi as DNS server
2. dnsmasq not reloaded after config change
3. Config file not created correctly

**Solutions:**

1. **Verify Device DNS Settings:**
   - On device, check network settings
   - DNS server should be Pi's IP address
   - If using DHCP, Pi should be providing DNS via dnsmasq

2. **Manually Reload dnsmasq:**
   ```bash
   sudo systemctl reload dnsmasq
   # Or restart if reload doesn't work
   sudo systemctl restart dnsmasq
   ```

3. **Check Config File:**
   ```bash
   sudo cat /etc/dnsmasq.d/blocked-domains-e6:6a:8f:19:be:b1.conf
   # Verify domain is in the file
   ```

4. **Test DNS Resolution:**
   ```bash
   dig @127.0.0.1 example.com +short
   # Should return 127.0.0.1 if blocked
   ```

### Issue: dnsmasq Not Reloading

**Symptoms:** Config file updated but changes not applied

**Solution:**
```bash
# Check dnsmasq status
sudo systemctl status dnsmasq

# Reload configuration
sudo systemctl reload dnsmasq

# If reload fails, restart
sudo systemctl restart dnsmasq

# Check for errors
sudo journalctl -u dnsmasq -n 50
```

### Issue: Config File Not Created

**Symptoms:** No config file in `/etc/dnsmasq.d/`

**Possible Causes:**
1. Script permissions issue
2. Script path incorrect
3. Script execution failed

**Solutions:**

1. **Check Script Permissions:**
   ```bash
   ls -l scripts/block_domain.sh
   # Should be executable (-rwxrwxr-x)
   ```

2. **Manually Run Script:**
   ```bash
   sudo ./scripts/block_domain.sh example.com e6:6a:8f:19:be:b1 0
   # Check for errors
   ```

3. **Check Laravel Logs:**
   ```bash
   tail -f storage/logs/laravel.log
   # Look for DomainBlockingService errors
   ```

4. **Check ScriptExecutor:**
   - Verify script is in whitelist: `app/Services/ScriptExecutor.php`
   - Verify script path is correct

### Issue: Multiple Devices Share Same Blocklist

**Symptoms:** Blocking a domain for one device affects all devices

**Possible Causes:**
1. MAC address normalization issue
2. Config file naming issue

**Solutions:**

1. **Verify MAC Addresses:**
   ```bash
   php artisan tinker
   ```
   ```php
   App\Models\Device::select('id','name','mac_address')->get();
   # Verify MAC addresses are in correct format (XX:XX:XX:XX:XX:XX)
   ```

2. **Check Config Files:**
   ```bash
   ls -la /etc/dnsmasq.d/blocked-domains-*.conf
   # Should have separate files for each device
   ```

3. **Verify MAC Normalization:**
   - MAC addresses should be uppercase with colons
   - Example: `E6:6A:8F:19:BE:B1` (not `e6:6a:8f:19:be:b1`)
